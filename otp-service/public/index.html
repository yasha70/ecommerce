Real-time mobile number verification

Drop-in OTP verification for any website: an embeddable widget plus a REST API, backed by the SMS gateway of your choice.

Try it

How it works

  1. User enters their mobile number in the widget.
  2. We generate a one-time code and send it by SMS.
  3. User types the code; we check it in real time.
  4. The widget hands your page a signed, single-use token.
  5. Your server confirms the token with its secret key and trusts the number.

In development the SMS is printed to the server console.

1. Register your website

npm run create-app -- "My Shop" https://myshop.com

You get a secret API key (sk_…, server only) and a public widget key (wk_…) that only works from the origins you list.

2a. Option A: embed the widget

<form action="/signup" method="post">
  <div data-otp-widget data-widget-key="wk_your_widget_key"></div>
  <button>Create account</button>
</form>
<script src="{{PUBLIC_URL}}/widget.js" defer></script>

After verification the widget adds a hidden otp_token field to the form and fires an otp:verified event. On your server, confirm it:

// Node.js example
const r = await fetch('{{PUBLIC_URL}}/api/v1/token/verify', {
  method: 'POST',
  headers: { 'content-type': 'application/json', authorization: 'Bearer ' + process.env.OTP_SECRET_KEY },
  body: JSON.stringify({ token: req.body.otp_token }),
});
const result = await r.json();
if (!r.ok) throw new Error(result.message);
// result = { verified: true, mobile: "+919876543210", verified_at: "..." }

2b. Option B: call the API from your backend

curl -X POST {{PUBLIC_URL}}/api/v1/otp/send \
  -H "Authorization: Bearer sk_your_secret_key" -H "content-type: application/json" \
  -d '{"mobile":"+919876543210"}'
# {"request_id":"req_…","mobile":"+91******3210","expires_in":300,"resend_after":30}

curl -X POST {{PUBLIC_URL}}/api/v1/otp/verify \
  -H "Authorization: Bearer sk_your_secret_key" -H "content-type: application/json" \
  -d '{"request_id":"req_…","otp":"123456"}'
# {"verified":true,"mobile":"+919876543210","token":"…"}

API reference

EndpointAuthBody
POST /api/v1/otp/sendsecret key{ mobile }
POST /api/v1/otp/resendsecret key{ request_id }
POST /api/v1/otp/verifysecret key{ request_id, otp }
POST /api/v1/token/verifysecret key{ token }
POST /api/v1/widget/{send,resend,verify}widget key + originsame as above

Errors return a non-2xx status with { error, message }; e.g. invalid_mobile, invalid_otp (with attempts_left), otp_expired, resend_cooldown / too_many_otps (with retry_after).
